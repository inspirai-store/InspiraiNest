# 积木

在资料空间的插件设置中启用「积木」，桌面/Web 导航出现入口。一个积木有多个目标，目标包含具备验收条件与依赖关系的部件。资料和记录以来源 ID、版本及原文引句引用，排除关联不删除来源。

## 长期推进

服务端每分钟补偿扫描新资料、记录版本和活跃积木；创建、加入、修改后也触发扫描。匹配任务冻结来源正文和目标，交由声明 `blocksProtocol:1` 的 Worker 使用现有 Agent 执行。结果经过条件、来源 ID 和逐字引句校验后自动归入；未完整取得的来源保持线索状态。记录中的主张不等于外部事实核验。单份来源输入上限 60,000 字符，超过上限或存在未读附件时按 partial 处理。

新版本触发重判；排除结果在同一来源版本下保留。变更目标或手动加入后撤销旧匹配任务的分配，迟到结果不能改写新目标。没有可用 Worker 时任务在队列中等待，失败和环境问题沿用处理中心的诊断、重试流程。

外部采集按部件缺口排队，默认每日最多五项，单积木一次一项；等待人工处理的部件不妨碍其他部件继续。暂停后不再安排新任务。原文和既有版本由原资料库保管。

## 手机

Android：记录详情「更多 → 加入积木」；资料阅读页「加入积木」；记录页「更多 → 积木」查看目标。记录先同步再加入。

iOS：记录详情「加入积木」；资料库工具栏「积木」可选择已有资料/记录和目标部件。分享内容沿用原有保存/同步流程，保存后进入记录详情加入。

## 评价和交接

只有完整、未失效、未排除的支持材料满足全部必备条件且依赖成熟时，目标才可交接；反证会阻塞成熟度。文章自动交给写作插件创建冻结版本的草稿任务；产品生成可下载的 JSON 材料包。写作插件停用时保留等待状态，系统不会自行启用插件。交接按目标和证据内容去重；用户后续修改稿件不会被覆盖。首版不执行产品开发或发布。

接口：`GET/POST /api/blocks`；`GET /api/blocks/materials`；`GET /api/blocks/:id/handoffs`；`POST /api/blocks/:id/{structure,join,link,exclude,pause,evaluate}`。修改要求当前 `revision`。Worker 仅凭有效分配令牌向 `POST /api/blocks/matches/:taskId` 提交结果。

验证记录见 `artifacts/blocks-2026-10-24/README.md`。
