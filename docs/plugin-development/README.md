## 当前可复用的基础

- 任务执行和回报：[worker.mjs](../../collector/src/worker.mjs) 的 `prepareWorkspace`、`taskPrompt`、`processTask`；保持任务隔离、已有成果、进度日志和待操作恢复。
- 授权、领取与派发：[server.mjs](../../collector/src/server.mjs)、[task-routing.mjs](../../collector/src/task-routing.mjs)；沿用执行凭据与 `assignmentId`，不让扩展自行发放权限。
- 技能包校验：[skill-package.mjs](../../collector/src/skill-package.mjs)；沿用文件清单、哈希、路径和疑似凭据检查。
- 技能任务快照与执行验证：[skill-runtime.mjs](../../collector/src/skill-runtime.mjs)、[skill-verification.mjs](../../collector/src/skill-verification.mjs)；安装、加载、真实调用分别取证。
- 轻量归档：[archive.mjs](../../collector/src/archive.mjs)；`source.json` 是条目入口，目录索引继续由 [catalog.mjs](../../scripts/catalog.mjs) 生成，离线阅读保持 `file://`。

这些是当前源码中已有的集成点，不是本次新增接口。平台特有登录态只留在明确授权的工作节点；分享入口也不自动获得平台读取会话。

## 建议实施顺序

以下是后续开发建议，不是已经排定版本或已交付功能。

| 阶段 | 最小交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0：明确合同 | 为一种来源确定输入、依赖、输出、错误、授权和验收样本 | 确认许可；用合成夹具覆盖失败和部分成功，不依赖本机绝对路径 |
| P1：正文试点 | 微信普通文章与图文卡片的可复现提取；接入现有技能及工作节点链路 | 在目标系统以固定版本实际调用；正文、时间、配图、上传和远端阅读全部核对 |
| P2：评论试点 | B站视频一级评论、回复、范围报告和断点恢复 | 真实多页样本验收；明确上限、缺失关系和附件；通过许可核对 |
| P3：需会话平台 | 公众号留言、自有视频号分别验证 | 用户明确授权的本地读取路径可持续使用；不是正文可读或扫码成功推断 |
| P4：分析与扩展 | 线程级有效内容分析；再扩展其他平台、增量与调度 | 结论能定位原文；人工样本验证质量；独立验收采集、分析及运行成本 |

先复用已存在的技能生命周期与任务流程，再决定是否需要通用扩展协议。不要为本次资料整理新建执行服务、数据库或未经验证的跨平台爬虫。

## 交付检查

1. 先读来源版本及验证日期；历史成功不代表今天仍可访问。本轮仅重新检查当前源码与本地 skill 的离线测试，没有重新登录平台或重抓真实评论。
2. 区分正文、配图、当前评论、内嵌截图、公开元信息和模型分析，分别记录能力与完整度。
3. 失败保留已取得成果；需要登录时回到原机待操作，不复制浏览器凭据，不更改授权记录。
4. 新增适配器使用合成夹具提交测试；真实原文、评论、运行目录、会话、证书和配置继续排除在 Git 之外。
5. 对正式条目执行 catalog build/check；对轻量包核对所有本地相对链接确实属于可上传附件。正文归档成功不等于工作节点上传成功。
