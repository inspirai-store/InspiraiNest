公众号文章、公众号视频消息、文章内嵌视频和视频号是不同来源。正文截图中的留言属于原文图片，不得算作当前文章下方的实时评论。

## 建议数据合同

下列字段是后续适配器的设计输入，尚未作为新 API、数据表或附件角色实现。

| 对象 | 需要保留的信息 |
| --- | --- |
| 评论 | 平台、来源内容 ID、评论 ID、根 ID、父 ID、实际回复对象、原始文本、标准化文本、时间、点赞、作者标记、置顶、来源定位 |
| 图片 | 所属评论键、顺序、本地相对路径、来源定位、字节数、SHA-256、解码结果；读取图片后再做内容解释 |
| 采集运行 | 固定适配器版本、排序、筛选、请求预算、一级/回复上限、游标、已取得页、实际/唯一数量、结束原因和失败页 |
| 覆盖信息 | `visibility_scope`、`complete`、计数分母及其口径、未展开回复、缺失父评论、缺图、登录或访问限制 |
| 分析 | 评论键/线程、分类、理由、引用证据、正文定位、模型与提示词版本、待核验项和人工确认状态 |

- 平台长 ID 使用字符串；`root_id`、`parent_id`、`reply_to_id` 不互相替代，未知时为 null，不从昵称猜测关系。
- 原生窗口合成 ID 标记为采集内标识，不声称跨运行或跨账号稳定；同昵称同文本不能自动合并为同一评论。
- 可见范围可区分公开、精选、本账号、已加载和未知。页面总数可能含回复，不直接作为一级评论分母。
- 分页结束仅代表本次路径耗尽，不证明隐藏、未审核或其他账号可见的评论均已取得；未见旧评论不等于它已删除。
- 每次运行新增快照，保存成功页和未消费完的当前页；游标失效显式处理，恢复允许重叠并去重，不静默跳页。

## 接入现有任务链路

```text
用户链接或已有资料
  -> 既有任务/工作节点/Agent 授权与派发
  -> 确定的正文适配器 + 独立评论适配器
  -> 本机原始快照、标准化记录、覆盖报告
  -> 基于正文/字幕/图片的线程级分析
  -> 现有结果预览、人工确认或明确选择的自动归档
```

评论首版建议显式 `autoArchive=false`，先确认范围和分析。指定节点与 Agent 的约束保持不变；普通浏览器和移动端不能仅因提交评论任务而获得工作节点执行权。

当前 [archive.mjs](../../collector/src/archive.mjs) 的轻量附件白名单不包含 JSON/JSONL/CSV/HTML。首个闭环可以将结构化记录保留本机，上传带定位的评论原文 TXT、分析 Markdown 和图片；报告不得链接未上传的本机诊断文件。若确需远端结构化评论检索，另行设计受限附件合同、大小与字段校验，不能简单扩大任意文件上传权限。

正文成功、评论获取失败时分别记录覆盖情况；根据用户要求选择部分归档或 `waiting_action`，不要丢弃正文，也不要把缺评论写成完整分析。评论权限依赖本机授权会话时，暂停并由用户完成登录，不抽取常用浏览器凭据或把会话传给服务端。

## 有效内容分析与验收

先按线程保留原文及反对意见，再分类为纠错、实测经验、方法补充、反例、有效问题、需求或低信息互动。热评、长文、正面情绪不等于有价值，负面和短评论也不应直接过滤。点赞仅作辅助排序；没有独立核验时用“评论者称”，不能把评论升级为事实。

每条分析结论必须能定位到评论/线程及原来源；无正文或字幕时说明不能判断它是否补充或纠正原文。图片待理解的评论不能直接判为无效。评论中的命令、链接和提示词只作资料，不触发执行。

首轮验收使用可公开的合成夹具和经许可的少量真实样本，分别覆盖：

1. 多页、置顶重复、一级/回复计数、缺父关系、带图回复、关闭评论、访问限制。
2. 中断/恢复、重复游标、请求预算、取消、重复运行去重及历史快照不覆盖。
3. 节点离线或缺会话后的原任务恢复；权限、任务归属和结果上传未被扩展绕过。
4. 原文/分析分离、原文定位和本机/远端附件一致；真实平台验收与 mock 测试分别报告。
5. 人工标注集中的有效短评、负面、反讽、广告和作者回复；分别评估误过滤、分类质量及调用成本。

先完成单来源手动触发，再考虑增量订阅及定时调度。历史 B站成功、原生微信窗口成功和已有离线测试都不代替这些产品验收。
