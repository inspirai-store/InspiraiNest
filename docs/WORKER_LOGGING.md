# 本机采集日志约定

日志回答三个问题：当前采集走到了哪一步、为什么需要操作、系统故障是否已经恢复。

| 类别 | 收集内容 | 显示与处理 |
|---|---|---|
| 采集过程 | 领取、来源获取、字幕/转录、整理、本机归档、校验、上传、完成或待确认 | 中文事件，关联任务，最新在上 |
| 来源障碍 | 公开内容无法取得、来源登录或访问限制，由采集程序明确上报 | 留在采集过程，说明已尝试的方法及下一步操作 |
| 系统问题 | 网络、HTTP、响应格式、设备授权、磁盘、程序启动/退出、模型与工具配置 | 独立问题列表，重复合并，展开看错误码、接口、首次/最近发生时间及处理建议 |
| 原始执行输出 | Agent stdout/stderr、旧版 Worker 日志 | 默认折叠，仅用于诊断；不能把其中的文字当成进度或当前状态 |

`waiting_action` 是流程状态，不能单独判断错误类型。新结果可通过 `category: source | environment` 明确原因；旧结果没有分类时仅显示“待操作”，不推断故障来源。系统问题阻塞任务时，采集过程记录其影响，技术原因在系统问题中查看。

每个结构化事件包含 `version/id/at/runId/domain/level/code/message`，任务事件增加 `taskId/stage`。时间在本机实际记录事件时生成，保存为 ISO 时间，界面使用北京时间并按时间倒序。Agent 的阶段上报通过任务目录内的 `collector-events.jsonl` 接收，界面标明记录来源，时间为本机接收时间。只允许规定的阶段，不解析普通 stdout 推测进度。

系统问题按问题键合并，保存首次时间、最近时间和次数；重复发生最多每 30 秒写一次更新，恢复时立即写入最终次数和恢复时间。任务尚未恢复的错误跨运行保留在待处理计数中，标注上次运行；重启不表示修复。任务成功上传后记录恢复。前次运行的非任务问题标为历史记录，不推断当前仍发生。正常心跳、空队列轮询不写日志。

结构化日志位于数据目录的 `worker-events.jsonl`，单文件约 2 MiB，保留两个轮转文件。界面有界读取各文件末尾，最多显示最近 300 项；原始诊断每文件读取末尾最多 24 KB。保留旧日志，不根据文件修改时间补造旧事件时间。日志保存失败不终止采集。

不记录请求/响应正文、令牌、配对码、环境变量或完整采集内容；已知 Worker 凭据、Bearer、敏感字段和 URL 令牌均脱敏。详细原始 Agent 输出仍只保存在采集电脑，查看时再次脱敏。窗口只通过用途限定的 `worker:activity` IPC 读取事件，原有 `worker:logs` 字符串接口继续用于原始诊断。

响应解析错误保留 HTTP 状态、方法和接口路径，避免把服务端 HTML 错误页误报为网络 `SyntaxError`。Windows 状态文件替换遇到短暂 `EPERM/EACCES/EBUSY` 时做有限短重试，再由周期更新重试；保留上一次完整快照，连续成功后才报告恢复，不删除状态文件规避失败。

Windows PowerShell 5.1 向原生程序传递 stdin 时可能使用 ASCII，把中文脚本内容变成字面问号；Python 的 `-X utf8` 无法还原这种上游损坏。每次原生管道调用需设置 `$OutputEncoding = [Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)`，不同调用不共享设置。任务工作目录提供 `node scripts/write-collection-json.mjs <相对路径> <UTF-8 JSON 的 Base64>`，使用 ASCII 参数写入协议 JSON，避免中文经过默认编码的管道；事件文件按 UTF-8 追加，元数据及结果文件原子替换。

阶段记录兼容开头的 UTF-8 BOM。损坏的中文说明进入独立 `STEP_ENCODING` 系统诊断，采集过程使用中文说明，原始文字在详情中保留。上传前检测标题、摘要、标签和采集说明的替换字符及连续问号，发现问题以 `ARCHIVE_ENCODING` 阻止上传并指出字段；修复元数据、重建索引后继续原任务，已完成的下载、转录和正文可以直接复用。

另一类已记录的历史采集故障是 Codex CLI 拒绝 `gpt-6.1-sol`。当时账号的 CLI 模型接口默认提供 `gpt-5.6-sol`，只读检查返回 READY；仅在当时本机 Worker 启动参数中固定该模型，不改全局 Codex 设置。这类待操作任务应在环境恢复后继续，不代表来源获取失败。截图中的无时间旧 `SyntaxError/EPERM` 只能确认故障类别，不能追溯其确切发生时间或断言具体代理、占用进程。
