# 插件架构

## 功能归属

核心负责原始收集、基础编辑、标签收藏、关键词检索、阅读预览、版本与附件完整性、同步冲突、导出、身份及插件宿主。AI 助手提供摘要/转录/OCR/Agent/Skills；写作提供会话、文章、历史和选区加工；实验室提供 Codex 实测。新知持有学习候选、目标、节点先修关系、掌握进度、复述练习和教学交接，以版本化来源引用连接核心资料；前沿更新由用户触发，写作仅通过宿主回调交接草稿。项目管理未来独立存放项目、看板、目标与人的任务，以内容 ID 关联核心资料。人的项目任务和系统加工作业不共用业务状态。

## 配置协议

- `GET /api/plugins`：已授权 owner 和 Worker 获取空间快照；返回 `protocol:1`、`revision`、`enabled` 及插件清单。
- `PUT /api/plugins/:id`：仅 owner，可提交 `{enabled, revision}`。修订过期返回 `plugin_config_changed`；依赖未启用返回 `plugin_dependencies`；依赖或作业阻止停用时返回 `plugin_busy` 和 `details`。
- 启用状态保存在现有资料库 `setting/plugins-v1`，沿用现有部署/身份命名空间。当前每个服务对应一个资料空间，不新增租户模型。
- 已有空间首次升级保留所有现有插件；新空间只默认启用 AI 助手。启动初始化在接受请求前完成。
- 客户端缓存按空间/身份隔离，换空间拒绝迟到结果。界面、服务端写入和 Worker 任务领取使用同一状态。
- 旧任务由插件注册的判定函数识别，新任务同时记录 `pluginId`。`pluginId:null` 的纯收集收据属于核心。

## 宿主接口与数据

注册表由 `plugins/*/plugin.json` 生成，并校验版本、唯一 ID、依赖和循环。官方插件随版本编译发布，使用共享组件。清单贡献导航、设置及加工能力，SDK 提供文本处理、内容回收站和任务接口。

插件业务使用宿主授予的集合访问接口，保留原有 writing-session 等集合名称、ID、版本及事务。新业务可使用 `scopedStore` 分配插件命名空间。插件不取得 DB 连接，也不导入存储驱动。已声明的插件依赖只能调用其 `api/` 公开执行契约，禁止导入其他插件内部实现。核心成果仍由核心持有，插件仅引用内容 ID。

停用保留专属数据与已保存成果。已有 GET 历史读取和核心回收站恢复可用；新增插件写入被服务端阻止。排队、分配和执行中的作业，以及启用中的依赖会阻止停用。旧任务的取消/完成流程继续负责收尾。

`POST /api/tasks` 首先将原始内容和已校验附件保存为核心记录；关闭 AI 后返回已完成的纯收集收据。AI 开启时加工作业引用该记录，保存和加工状态相互独立。

## 多端支持

| 端 | 宿主接入 | 界面实现 |
|---|---|---|
| Web | 同源 Cookie 会话、HTTP、浏览器存储 | 与桌面共用 React 工作台 |
| Windows/macOS | 受限 IPC、系统授权存储、Worker | 共用 React，保留平台适配 |
| Android | 空间快照缓存、原生插件设置 | 保留 Compose 和现有嵌入写作 |
| iOS | Codable 空间快照、原生插件设置 | 保留 SwiftUI、分享扩展和现有 WebView |
| CLI | 现有只读协议与生成的插件数据契约 | 保留 Go CLI |
| Worker | 心跳时刷新空间能力，按启用状态维护扩展环境 | 无产品页面 |

平台注册表示现有能力可接入，不声明页面逐项对齐，也不声明 iOS 全面原生化完成。

## 构建与迁移

单一源码位于新目录；旧 `collector/src` 为转发模块。运行时默认数据位置保持兼容，`tooling/layout.mjs` 解析已迁移的源码资源；该兼容定位不改变用户数据路径。离线 Worker 工作区打包独立工具，复制后不依赖开发仓库。

根 npm 锁文件统一依赖；Electron/Docker/Gradle/XcodeGen/CI 使用规范目录。运行 `npm run plugins:generate` 更新注册表，`npm run check:boundaries` 检查核心不导入插件。构建、自动化 GUI、签名、真机和发布验收分别记录。
