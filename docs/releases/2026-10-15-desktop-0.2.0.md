# Desktop 0.2.0

0.2.0 starts the shared React desktop UI release series for macOS and Windows. It carries the existing 0.1.33 implementation forward without changing storage paths, application identity, dependencies, or runtime behavior.

## Included changes

- Shared navigation and page layouts for records, the library, tasks, settings, nodes, Agents, skills, updates, and diagnostics.
- Account-scoped local records and drafts, with legacy IndexedDB data, attachment Blobs, record versions, and idempotency keys retained. Account switches discard stale UI responses; capture requests also check the device authorization.
- Registered archive attachments resolve relative to the current Markdown document. Existing preview and download components handle supported resources; archive boundaries and restricted IPC remain in place.
- Consistent user-facing errors and concise controls such as 停止, 更新, 加工, 编辑, 保存, and 重试. 停止 retains graceful Worker drain semantics.
- Stable inline image components while scrolling Markdown content.

## Version and packaging

The collector and desktop package manifests and lockfile root entries are all 0.2.0. Both electron-builder targets derive installer filenames and update metadata from this version. The private frontend build package keeps its internal version; it does not determine the installed client version. Mobile versions are unchanged.

macOS uses the existing Developer ID signing and notarization workflow. Local-only builds set `publish_macos=false`; this does not publish an update feed or mark runtime acceptance as complete.

Windows uses the same desktop code and the existing NSIS x64 target. Its dedicated packaging, installed-client regression, data/configuration preservation, and platform-specific lifecycle checks remain a separate acceptance batch. The current Windows CI still needs frontend dependency installation and migration of legacy DOM checks to the React UI before it can serve as release evidence. A version bump alone is not Windows acceptance.

## Validation status

The inherited 0.1.33 source baseline passed 125 frontend checks, strict TypeScript/Vite build, and 23 native lifecycle checks. Signed macOS 0.1.33 installation and preservation checks were performed separately. Final account and body-link runtime regression was blocked by a macOS Keychain authorization failure; this remains open and is not resolved by changing the version.

The 0.2.0 signing run, package checks, installation status, and remaining runtime differences must be recorded in the release delivery evidence. No Windows installation or production update-feed publication is claimed here.
