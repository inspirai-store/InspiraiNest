# Windows 微信“转发到其他应用”接入计划

- 计划日期：2026-10-18（北京时间）
- 状态：已规划，待 Windows 开发；下列实施及验收任务均未完成。
- 实施仓库：`inspirai-store/InspiraiNest`，Windows Electron 桌面客户端。
- 源码核对基线：`ab7415a`（公开 `main`，桌面源码版本 `0.2.13`）；这是计划依据，不是本功能的发布版本。
- 排期：纳入后续 Windows 版本，按 W0 → W1 → W2 → W3 → W4 → W5 顺序推进。具体版本号、负责人和日期在启动 Windows 开发时填写。
- 本次交付：计划文档及文档入口；不实现接收器、不注册身份包、不改变安装器、不构建或发布客户端。

## 1. 目标与完成定义

用户在 Windows 微信的“转发到其他应用 / 选择电脑中的应用”中看到灵藏的名称和图标，选择后，灵藏在未启动和已经启动两种状态下，都能保存收到的内容并打开导入界面。用户检查内容后，继续使用现有的记录、同步及加工流程。

首版范围包含文本、链接、图片、现有附件流程支持的普通文件，以及经真实载荷确认后的微信聊天记录。首轮先打通普通内容接收，再完成聊天记录文本与附件解析，最后进入正式 Windows 版本验收。若聊天记录尚未通过实测，只能标记为普通分享接收里程碑，不能宣称整个微信接入完成。

保留现有 Electron 客户端和 NSIS 安装方式，增加 Windows 原生分享接收程序及 MSIX 身份包。Tauri 迁移、其他桌面平台的系统分享入口、通用 ZIP 浏览器及聊天数据库读取不在本计划范围内。

## 3. 技术方案

```text
微信选择灵藏
  → Windows 激活原生 ShareTarget 接收程序
  → 读取 ShareOperation，复制文本、链接、文件或位图
  → 将内容完整写入当前 Windows 用户的本地分享收件目录
  → 以请求 ID 唤起 Electron，或通过第二实例通知现有进程
  → 主进程校验、登记接收结果，通知现有记录界面
  → 用户检查并保存；后续按现有行为同步或主动加工
```

### 3.1 原生接收器与身份包

计划优先采用 **C# + Windows App SDK** 的独立 x64 接收器；W0 先验证该技术组合在目标系统上的实际分享激活。固定所用 .NET、Windows App SDK 和 Windows SDK 版本，随安装包交付所需运行时或明确安装依赖，在无开发工具的干净 Windows 机器上验证。

通过 `AppInstance.GetCurrent().GetActivatedEventArgs()` 识别 `ExtendedActivationKind.ShareTarget`，取得 `ShareTargetActivatedEventArgs.ShareOperation`；保持异步读取期间进程及线程环境有效，直至完成状态报告。不得把 UWP 的 `OnShareTargetActivated` 直接作为桌面程序入口。[S1][S3]

MSIX 身份包包含名称、图标、原生接收器入口、`windows.shareTarget`、所需能力及 `AllowExternalContent=true`。稳定的 `Identity.Name`、`Publisher`、`Application.Id` 在 W0 确定；`Publisher` 与实际签名证书主体一致，接收器可执行文件的身份清单与包保持一致。Electron 继续使用既有应用身份和数据目录，避免重置登录、Worker 配置及本地记录。[S2]

分享功能的系统下限以 Windows 10 2004 / Build 19041 为起点，再核对所选运行时是否要求更高版本；最终下限取两者较高值，并覆盖 Windows 11。低于下限时跳过分享注册，保留原客户端安装行为。[S2]

格式声明与实际能力对应：

| 输入 | 接收与业务处理 | 清单策略 |
| --- | --- | --- |
| 文本 | 保存完整文本、换行及 Unicode 字符 | `Text` |
| 链接 | 保存链接和伴随文本；运行时检测 `WebLink` 等实际格式 | 按微软清单使用 `Uri`，在微信实测确认；用户材料中的 `URI` 只视为原样记录 |
| 图片 | 读取 `StorageItems` 或 `Bitmap`，保留文件原件；位图流保存为可导入图片 | `StorageItems`、`Bitmap` 及已支持图片扩展名 |
| 普通文件 | 复制后复用现有附件类型校验；无文本也可导入 | 按实际附件能力列出扩展名 |
| 聊天记录 | 根据实测决定 ZIP 或其他载荷的适配器 | 通过相应解析与保全测试后才增加对应声明 |

不直接照抄 `SupportsAnyFileType`。如果微信不展示，先比对实际格式与声明；只有产品能完整保存并交付相应文件时才评估扩大声明，并记录前后对照结果。文件夹、未知格式及不支持类型给出实际处理结果，不静默忽略。此处遵循微软“只声明能够处理的类型”的建议。[S1][S3]

### 3.2 本地交接与完成语义

首版采用**持久化收件目录 + 请求 ID 启动参数 + 接收回执**，暂不引入命名管道或监听端口。接收器按 Windows 用户目录定位共享根目录，Electron 使用同一位置；规划位置为 `%APPDATA%\LibraryWorker\share-inbox\<requestId>\`，不依赖按配置派生的 Electron `userData` 路径。

- 接收器在分享数据权限有效时完成复制；先写暂存目录，内容完整后原子提交 `manifest.json` 和就绪状态。不能只保存微信临时文件路径。
- 交接清单包含 `schemaVersion`、UUID `requestId`、带时区的接收时间、实际数据格式、文本、链接及附件的相对路径、原文件名、字节数、SHA-256。来源应用信息按实际可取得内容记录，不凭启动参数断言来源。
- 启动参数拟为 `--inspirainest-share=<requestId>`，只传标识，不传正文、令牌或任意文件路径。原生程序通过确定的安装路径及参数数组启动主程序。
- 主进程校验请求 ID、目录边界、清单及文件完整性；分别处理首次 `process.argv` 与 `second-instance`，界面未就绪时先排队。保留既有 `--startup` 和 `--remote-update` 行为。
- 主进程按 `requestId` 持久化接收登记并写回执；相同请求重复激活只进入一次导入队列。用稳定的导入标识串联收件登记与记录存储，覆盖“记录已写入、回执尚未写入即崩溃”的重启去重。
- `ReportStarted` 表示开始接收，`ReportDataRetrieved` 在所需数据完整复制后报告；仅在主进程确认已可靠接管本地队列后 `ReportCompleted`。这里完成的是本地接收，不表示云端同步或 AI 加工完成。[S3]
- 唤起失败、复制失败或超时未获回执时报告失败；保留已完整保存的请求供下次启动恢复，避免丢失内容。只在导入持久化成功或用户明确丢弃后清理相应原始副本。

收件目录仅供当前用户使用。校验相对路径、链接/重解析点及实际大小，避免读取目录外文件；将容量及文件数量限制与现有附件规则对齐，接收器、主进程和界面一致拒绝超限输入。目录和日志不包含授权凭据，日志默认不记录聊天正文。

### 3.3 主应用导入与聊天记录

复用 `records` 模块的附件准备、本地存储、账号隔离、同步与加工入口。新输入先作为独立待导入内容保存，不覆盖已有编辑草稿、不拼接到当前正在编辑的记录、不自动启动 Agent。已有草稿时由用户选择新建记录或主动合并。

未登录或离线时仍可本地保留和查看。分享队列在交接时不能确定业务账号；在用户选择导入时绑定当前资料空间，之后沿用原账号隔离规则。未绑定内容不能因登录或切换账号而自动上传；已绑定内容不能转入其他资料空间。

聊天记录适配以 W1 取得的脱敏样本为依据：

1. 保存原始载荷和实际目录清单，确认文本编码、消息边界、时间信息、媒体引用及来源描述。样本只使用测试会话；个人聊天原文不进入公开仓库。
2. 若实际交付为 ZIP，单独解析并保留压缩包；检查解压路径、链接条目、数量和展开大小，不自动执行或打开附件。现有普通附件支持不能当作 ZIP 已受支持。
3. 对简体、繁体或英文文件名，仅在样本确认后加入识别规则。保留原文，不猜测缺失的发言人或时间；解析文本与原始文件分开保存。
4. 预览文本及关联附件，再交由用户保存。缺失媒体、无法解析、加密或不支持的文件明确显示状态，并保留原始载荷；不能将部分解析标记为完整聊天记录导入。

界面沿用现有组件，只增加必要的内容、选择、进度、错误及重试操作；不添加与操作或 UI 效果无关的解释性、提示性小字。

### 3.4 安装、升级、卸载与签名

扩展现有 x64、按用户安装的 NSIS 流程，使用 `Add-AppxPackage -Path <msix> -ExternalLocation <installDir>` 为实际安装用户注册。路径始终按字面值及独立参数传递，覆盖中文和空格。核对安装/更新提权时的用户上下文，避免注册到管理员或构建账号名下。[S2]

身份包、接收器及主程序随同一安装包发布；在 Windows 构建中把原生文件放到 `extraResources` 对应目录，并确保 `ExternalLocation` 与清单中入口的相对路径一致。沿用一个稳定包身份，制定应用 SemVer 到四段数字包版本的单调映射；同版本重装先检测已注册状态，避免无条件重复注册。

覆盖首次安装、修复、覆盖升级、应用内更新、安装目录变化及卸载。更新前等待活动接收器退出或完成接收，处理文件占用；更新后重新核对版本、外部目录和扩展声明。注册失败保留普通客户端功能，提供可操作的失败及重试状态，不能显示分享已启用。卸载先注销本用户的精确包身份再移除程序；保留现有 `deleteAppDataOnUninstall: false`，不删除用户资料、配置和待处理输入。旧版本回退需单独验证包降级处理，不假定普通覆盖安装能降低身份包版本。

开发自签名证书仅用于明确配置的测试环境。正式分发前验证身份包签名在目标电脑受信任，接收器及安装器完成既定签名策略。证书私钥和口令留在受控签名环境；公开 CI 只构建测试产物，不因本功能取得生产签名权限。没有可用的正式信任链时，此项记为发布阻塞，不能把开发证书安装成功当作面向用户可交付。[S2]
