# 工作节点版本与远程客户端更新

工作节点列表与详情显示客户端版本和正在运行的 Worker 版本。旧版没有单独上报 Worker 版本时显示“旧版未单独上报”，不以管理端登录版本推断后台进程版本。信息来源于已授权节点；断线后沿用页面的缓存状态提示。

0.1.24 起，正式安装的 Windows/macOS 客户端可以接收管理端的更新请求。旧版节点必须先在本机安装支持该协议的版本。只读授权、浏览器和手机不能作为更新目标；管理端可以从桌面工作台或网页的节点详情发起更新。不同平台只有发布了对应的正式安装包才提供更新。

更新请求固定版本、平台、架构、大小和 SHA-256，不允许提供下载地址、命令或执行参数。节点使用原有正式更新器下载，另行核对固定的安装包哈希。安装包校验通过后，等待当前任务结束并安全停止 Worker，安装、重新启动，再向服务端确认实际版本。只有新版本重新上线才显示成功；退出前保留运行或暂停意图。

离线节点可以排队；未开始安全停止前可以取消。请求编号用于处理超时重试，重复请求不会创建新的更新任务。撤销节点授权会取消请求；安装前再次核对授权。排队超过 24 小时、执行超过 2 小时或安装后 15 分钟仍未确认会显示超时，不会报告成功。更新安装失败保留原始授权和任务数据。

0.1.25 起，一台电脑对应一个客户端身份，资料管理与后台采集是同一客户端的能力。桌面升级后在主进程内提交两份旧凭据的证明，核对同服务域完整 SMBIOS/IOPlatform 硬件身份及安装绑定，再将旧登录凭据迁为原工作节点的兼容凭据。设备页只有一个名称、一个设备 ID、一个撤销入口；工作节点 ID、用户命名、原任务、心跳和版本记录均保留。仅发现相同型号或短硬件标识不会迁移，浏览器、手机和只读授权也不会与电脑合并。

兼容凭据只用于原有用途，不产生第二个客户端；撤销客户端时全部凭据一起失效。后台 Agent 不持有资料管理凭据，资料管理凭据继续由主进程使用系统安全存储保存。旧安装绑定及授权记录作为内部兼容映射保留，回滚服务后旧凭据仍可使用。迁移可重复提交，支持多服务实例并发，失败不更改原配置；同一安装重新登录保留原节点 ID 和名称。

隔离测试覆盖更新请求、权限、重复提交、取消、撤销、版本变化、包校验、安全停止、重新上线确认和多尺寸页面。自动化安装器为测试替身；实际跨电脑更新安装仍需要真机验证。
